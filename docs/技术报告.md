# 技术报告：脚手架与模板支架安全验算及危大分级工具（sfc）

> 版本：0.5.0（M5 桌面交付）｜日期：2026-10-07
> 摘要：本项目把"脚手架/模板支架专项方案的安全验算、条文核查与危大分级"做成
> 全离线、可复现、带内置基准的桌面工具。数值结论全部来自确定性规则与已核对
> 条文数据，零 LLM 通路、零联网 API；CLI 与 GUI 双通路共用同一引擎。

## 1. 问题与总体思路

施工专项方案审查中存在三类高频痛点：

1. **验算靠手工套公式**——JGJ 130-2011 / JGJ 162-2008 的立杆稳定、水平杆、
   连墙件、地基承载力等验算重复量大、查表易错；
2. **方案"两张皮"**——方案正文参数与验算书取值不一致，人工比对容易漏；
3. **危大分级靠记忆**——住建部令第 37 号与建办质〔2018〕31 号附件的规模界限
   与义务要求难以逐条对应到具体工程。

工具形态：输入参数卡（手填 JSON / GUI 表单）或专项方案文档（docx/pdf），
输出验算结果（表达式/代入/比值/限值/结论/条款号）、违规清单（含整改建议与
原文摘录）、危大分级结论（含义务与依据摘录），并可导出 docx 验算书/核查报告。

三条主线纪律贯穿始终：

- **条文纪律**：未经原文核对（status=待核对）的条文数值不得进入计算/判定路径，
  引擎与规则运行器双层硬拦截；
- **确定性**：解析=正则/关键词/表格行匹配，核查=规则表，分级=自研三值条件
  求值器（不 eval）；结论只由确定性比较产生；
- **可复现**：内置基准零 API 离线，冻结 fixtures 位级一致，报告产物无时间戳、
  同输入两次生成字节相同。

## 2. 验算公式编码方案

### 2.1 数据三层：原文 → 要点条款库 → 机器表

- **原文层**（`data/knowledge/raw/`，gitignored，版权红线）：规范全文只存本地，
  sha256 记入数据台账，绝不入公开仓与打包产物；
- **条款库**（`data/knowledge/clauses/`，74 条 + 公式表 22 条 + 阈值表 36 条）：
  每条 = 条号 + 要点转述 + status（已核对/待核对）+ source（规范号+条号+渠道），
  "要点+出处"形式规避全文转载；危大清单 `panorama.json` 9 条目逐条挂 31 号文
  附件原文摘录；
- **机器表**（`engine/tables.py`）：表 A.0.6 φ 值 251 档、表 A.0.1 gk 矩阵、
  表 5.2.8 μ、表 A.0.5 挡风系数——从原文表图双读转录，配锚点对账测试
  （抽取若干档位与原文截图数值逐一核对）。

### 2.2 参数卡：构造时校验，非法拒收

所有验算输入走统一参数卡 schema（`engine/card.py`）：字段存在性、正数性、
枚举值在**构造时**校验，非法即 `CardError`（消息面向用户），错误输入进不了
引擎。规范限值类校验（如 JGJ162 立柱步距 ≤1.8m）在模块内经条款库取值执行——
限值必须挂已核对出处，未核对过的"经验上限"一律不加。

### 2.3 验算模块与结果契约

6 个验算模块（M-1/M-2 立杆稳定不组合风/组合风、M-3 纵横向水平杆、M-4 连墙件、
M-5 立杆地基、M-6 模板支架立柱+地基）统一契约：

```json
CalcResult = {
  "module_id": "M-1",
  "status": "ok | blocked",
  "checks": [{"item","expr","substituted","ratio","limit","verdict","clause_refs"}],
  "detail": {"中间量": "..."}     # 与算例真值库逐项对账（0.02 容差）
}
```

- verdict 只由确定性比较产生（ratio ≤ 1 → pass）；
- 表达式与代入分两列存（如 `N/(φA) ≤ f` 与 `N=5.4288 kN, φ=0.186, A=506 mm²
  → σ=57.682 N/mm² ≤ f=205`），报告直接渲染；
- `status=blocked` 表示依赖条文未核对——返回时不带任何计算数值（测试锁定
  "blocked 验算书不渲染任何计算数值"）。

### 2.4 真值回归

`data/examples/` 13 例算例真值库（来源=规范条文算例，逐项挂条款号，生成器
逐量复算断言）：每例 input_card + expect（checks 比值容差 + 中间量 0.02 容差
+ 条款号集合），回归测试与 bench examples 套件同口径对账，13/13 通过率 100%。

## 3. 条文核对流程

1. **定位**：模型内部记忆只用于"该查哪部规范哪个条号"，不用于回答数值；
2. **取原文**：官方渠道直连优先（mohurd 两文件直连成功），JGJ 规范经权威
   规范库全文 HTML + 原图转录 + 多渠道交叉核对，逐字条文 curl 落盘后本地提取；
3. **入库**：要点转述 + status=已核对 + source（规范号+条号+渠道）；查不到
   的条目标"待核对"继续推进，不空转；
4. **拦截**：引擎 `Knowledge.unverified()` 模块级体检 + `Knowledge.threshold()`
   取值级校验双层拦截——任一依赖待核对，整模块拒绝出数；
5. **守门**：条款库 100% 挂出处或显式待核对（测试常驻）；`sfc bench` 达标
   门限把"条文数据被动过"变成一条命令可见。

## 4. 合成方案数据设计

真实专项方案难以获取且无标注真值——用**程序化生成器**（`synth/generator.py`，
固定 seed=20261006）自制带真值评测集：

- **确定性生成纪律**：自研确定性 RNG（splitmix64，不用 stdlib random——不承诺
  跨版本序列一致）、产物无时间戳、两次生成位级一致（守门测试常驻），12 个
  冻结 fixtures 入仓，改体例必须整目录重生成提交；
- **注入缺陷组**：步距超限、连墙件间距超限、剪刀撑缺失、两卡不一致（两方向）、
  分级参数缺失/超规模，每 fixture 的 truth 记 main_expect + also_expect——
  真值语义 = "全部非 pass 集合"（同一注入隐含的其余结论也要被检出，防漏报
  伪装成正确）；
- **评测器**：解析+核查管线输出中 verdict≠pass 的 findings 与期望集合对账，
  rule_id+verdict+数值容差+条款号包含四重匹配 → TP/FN/FP → 检出率/误报率/F1。

内置基准（`bench/`，`sfc bench` 一条命令，全部零 API 离线）：

| 套件 | 规模 | 指标 | 门限 | 当前值 |
|---|---|---|---|---|
| examples | 13 例算例真值 | 通过率 | 100% | 100%（13/13） |
| synthetic | 12 fixtures | F1 / 误报 | ≥0.95 / 0 | **1.0 / 0**（检出率 100%） |
| grading | 35 例边界值用例 | 通过率 | 100% | 100%（35/35） |

grading 套件覆盖 31 号文边界值：落地架 23.9/24.0/24.1m、49.9/50.0/50.1m、
悬挑 20m、附着 150m、承重 7kN、模板支撑 5 条件全边界 + pending 语义 2 例。

## 5. 方案核查与危大分级

### 5.1 解析（规则优先，宁缺勿错）

docx（python-docx 表格+段落）/pdf（pypdf 文本路线，零识图）→ 统一中间表示
（方案卡+验算书卡，条目制：value/unit/confidence/evidence）：

- 置信度分层：参数表逐行 0.99、正文正则与关键词在位 0.85、多值冲突强制 0.5；
- 低于 CONFIDENCE_MIN=0.7 或取值缺失 → `unknown_slots`（宁缺勿错），核查跳过
  该槽位记"待人工确认"而非硬判；
- 章节限定提取（工程概况/危大管理节），防构造措施模板句污染全文正则。

### 5.2 核查规则表

`rules/checks.json` 12 条规则（threshold/presence/consistency/grading 四类），
运行器特性：

- **类目门控**：only_if 关键词 AND 全命中 project_type 才生效，跨全部 check_type
  一致生效（防跨类目误查参数——如悬挑架不查落地架步距限值）；
- **限值不写死**：一律 limit_ref 挂 thresholds.json（步距双限值 1.8/2.0 分档
  挂表 6.1.1 与 A.0.1 查表域）；
- **两张皮定级**：方案实况劣于验算书取值=不合格（未被验算覆盖），优于=提示
  （验算偏保守），两方向均记 violation——超容差即违规，方向只定级别；
- **结论挂依据**：每条 finding 带条款号与整改建议，核查报告回填原文摘录
  （knowledge 回填，查不到静默跳过）。

### 5.3 危大分级（三值逻辑，不 eval）

`grading/`：类型识别（关键词优先级表）→ 参数提取（卡值+显式覆盖）→ 31 号文
附件条件表达式（如 `24 <= build_height < 50`）由**自研三值求值器**执行：
True/False/None，None=参数缺失 → pending 待人工确认，不猜值。判定序
chaoguimo→weida→none 取首个 True；依据 basis 全部已核对才出确定结论。

## 6. 桌面交付（M5）：GUI 与打包

### 6.1 GUI 只消费引擎 API

PySide6 五页签（验算/方案核查/一致性/危大分级/基准），分层：

```
gui/pipelines.py   ← GUI 侧唯一编排层（零 Qt）：与 CLI 同款引擎函数调用
gui/specs.py       ← 验算页动态表单字段规格 + 默认卡（转录自带真值算例）
gui/*_tab.py       ← Qt 表现层：只做表单采集、结果展示、导出对话框
```

任何判定逻辑不在 GUI 层复现——CLI 与 GUI 是同一引擎的两个出口。导出按钮
按 CLI 同款编排后调 `generate_calc_report/generate_check_report`（report/ 是
纯渲染器，吃 result dict）。

三条实测工程纪律（offscreen 三坑）：

1. `QT_QPA_PLATFORM=offscreen` 必须在**首次导入 PySide6 前**设置（测试模块头）；
2. 模态 QMessageBox 会挂死 offscreen 测试批——页面通知走可注入 `notify` 信号，
   文件对话框只允许出现在按钮槽内（测试 monkeypatch 屏蔽）；
3. offscreen 平台拿不到系统字体（中文渲染成方块）——演示截图走 native QPA +
   `widget.grab()`（无需 show 上屏），存图走 QBuffer（6.6 的 QPixmap.save
   (BytesIO) 不可用）。

GUI 测试 21 项（offscreen，声明式跳过：未装 PySide6 的环境整模块 skip）；
`--probe` 无头自检供打包后存活探针（offscreen 建窗+页签校验，退出码判定）。

### 6.2 PyInstaller onedir 双 exe

- **双 exe 单 dist**：`sfc.exe`（CLI 控制台，console=True，与开发态同一 main
  ——无 Python 机器的脚本化验证通路）+ `sfc-gui.exe`（桌面，console=False）；
- **数据内嵌冻结分支**（`loader.find_data_dir`，分支测试锁死）：
  显式参数 > SFC_DATA 环境变量 > `sys._MEIPASS/data`（PyInstaller 运行期解包根）
  → `<exe目录>/_internal/data`（6.x 布局兜底）→ `<exe目录>/data`（5.x 布局兜底）
  > CWD 上溯 > 包相对上溯。冻结分支整体排在 CWD 上溯**之前**——exe 在仓库树内
  跑也吃内嵌数据，杜绝"内嵌数据验了个寂寞"的假结果陷阱；
- **spec 白名单双守门**（`packaging.py` 单一事实源）：datas 只能由
  `build_datas()` 产生（包内 checks.json + knowledge/clauses/*.json +
  examples/*.json + synthetic/*，共 46 份）；禁区路径段（规范原文全文目录）
  在白名单构建时即抛错；spec 文本断言禁止手写数据路径；
- **构建后断言**（`tools/build_exe.py --check`，exit 1 阻断）：dist 全树禁区
  成分扫描 + 内嵌数据逐份 sha256 与仓库对账 + 白名单外多余文件检测；
- **hiddenimports 显式覆盖**惰性导入的外部依赖（docx/pypdf）——漏一个即
  冻结 exe 缺核心能力而源码态测试全绿的静默坑；
- **版本通道实测**：Python 3.8.8 → PySide6 锁 6.6.3.1（6.7+ 元数据要求 ≥3.9，
  extras 写上限 <6.7 防干净环境解析到破坏版本）；PyInstaller 锁 5.13.x
  （6.x 在 py3.8 上 modulegraph 扫 dis 指令随机崩）。

### 6.3 干净环境验证（发布门预演）

中立目录（%LOCALAPPDATA%\Temp）+ `env -i` 剥离 PATH（含 PYTHONPATH/SFC_DATA/
代理变量）下：selfcheck（数据目录=内嵌副本）、calc exit 0、check exit 1
（含违规，降级完成语义）、grade exit 0、**bench exit 0（三套件全达标——
exe 完全离线靠内嵌数据跑通全部基准）**、report calc exit 0 / report check
exit 1（含违规降级）、GUI 探针 exit 0（5 页签+内嵌数据）。

## 7. 质量门与可复现性汇总

- 测试：**304 项**（M4 基线 255 不回退 + M5 新增 49：冻结分支 10/GUI 21/打包 16
  (含 5.x 布局)/CLI gui 2/EOL 门既有），全绿 @Python 3.8.8 venv；
- 基准：`sfc bench` exit 0（三套件门限全达标，指标见 §4 表）；
- 报告：无时间戳（签署栏手填）、零外链（rels 无 External）、同输入两次生成
  位级一致；
- 数据：`tools/gen_examples.py --check` / `tools/gen_synthetic.py --check`
  位级一致；EOL 门（全树文本 CR 检测）常驻；
- exe：干净环境（剥离 PATH）五连+GUI 探针全过；dist 无禁区成分；内嵌数据
  与仓库逐份 sha256 一致。

## 8. 限制与边界（诚实声明）

1. 规范覆盖面：JGJ 130-2011（扣件式钢管脚手架）、JGJ 162-2008（模板支架）
   主要验算项；碗扣式/门式/附着升降等类型仅做危大分级，不做验算；
2. PDF 解析为文本路线（零识图）：扫描件/图片型 PDF 不可用，表格参数将进
   unknown_slots 记待人工确认；
3. pipe_spec 暂只支持 48.3×3.6 钢管；
4. GUI 基准页运行为同步执行（秒级，按钮期间忙态光标），不设后台线程；
5. 全部结论为**辅助审查意见**，不替代注册结构工程师/专项方案审查程序；
   条文数值以现行规范正式文本为准（详见免责声明）。
