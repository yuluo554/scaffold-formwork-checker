# 05 数据计划与里程碑

## 1. 数据目录与台账规则

| 目录 | 内容 | 入仓策略 |
|---|---|---|
| `data/knowledge/raw/` | 规范/文件**原文全文**（PDF 等） | **不入公开仓**（版权红线），.gitignore；本地留存，sha256 登记台账 |
| `data/knowledge/clauses/` | 条款库 JSON（要点+条款号+出处+status）、公式表、阈值表 | 入仓（要点+出处形式，规避全文转载） |
| `data/examples/` | 算例真值库（规范算例/教材算例 JSON） | 入仓，逐例登记来源 |
| `data/synthetic/` | 合成专项方案 fixtures（字节冻结）+ 真值 | 入仓；禁止手改，改体例→固定 seed 重新生成整目录提交 |
| `data/README.md` | 台账：每份数据=来源+许可+sha256+status | 入仓，持续维护 |

铁律：**无出处的数值不得作为基准真值**；条款条目全部挂出处（规范号+条号+渠道）或显式 `status=待核对`。

| 住建部令第 37 号 | 危大定义、专项方案编制/论证义务条款 | 政府官网原文（gov.cn） | 全文 PDF 在案 ✅，条款未入库 ⬜ |

查证纪律（承接方法论）：模型记忆只用于定位"查哪部规范哪个条号"；逐字条文 curl/WebFetch 落盘 `raw/` 后本地提取，不靠搜索摘要转述；摘要工具出现的链接一律不采信，只信直连原文。两渠道全败→条目标"待核对"继续推进，不空转。

## 3. 算例真值库设计（examples/）

```jsonc
{
  "example_id": "EX-lizhigan-001",
  "title": "立杆稳定性（不组合风）教材算例",
  "source": {"book": "《...》", "edition": "...", "example_no": "...", "page": null},
  "input_card": {"...": "完整参数卡"},
  "expect": {
    "checks": [{"item": "lizhigan_stability", "ratio": 0.83, "tolerance": 0.02, "verdict": "pass"}],
    "tolerance_note": "容差按算例舍入位数定；φ 查表类中间量放宽"
  }
}
```

配套：参数扫描回归（每模块对关键参数做扫描，锁定输出单调性与边界行为，防公式改错只对单点真值）。教材算例选型标准：计算步骤完整可复算、参数取值与规范表可对账、结果带中间量（便于定位差异）。

## 4. 合成专项方案生成器设计（synthetic/，M1 建，M3 消费）

- **确定性纪律（字节冻结根基）**：禁 stdlib random/set 迭代序/系统时钟——自研确定性 RNG（splitmix64）；落盘 docx 无时间戳字段可清则清（docx zip 元数据用固定值覆写）；两次构建逐字节一致，配"再生成位级一致"守门测试；生成目录整体作为冻结 fixtures 入仓，禁止手改。
- **体例**：python-docx 生成专项施工方案文本（工程概况/搭设参数表/构造措施/验算书章节），参数从模板池按确定性序列抽取（合法组合来自条款库已核对限值）。
- **注入缺陷类型（每例主期望+隐含 also_expect）**：
  1. 步距超构造限值（threshold 类）
  2. 漏剪刀撑 / 漏连墙件（presence 类）
  3. 连墙件间距超限（threshold 类）
  4. 两张皮：验算书章节取值与方案正文不一致（consistency 类）
  5. 应专家论证（超规模）而方案未标注（grading 联动类）
  6. 干净对照组（0 缺陷，误报率分母）
- **真值语义**：注入项记主期望；同一注入隐含的其余结论记 also_expect；评测按"文档全部非 pass 集合"对账（防漏报伪装成正确）。
- 互斥坑当场记录（同一参数两处注入打架、多值封顶、先清旧行）。

## 5. 里程碑计划（M1-M6，每个里程碑都有可演示物）

### M1 数据先行（条款库+阈值清单+算例库+生成器）

- 产出：`knowledge/clauses/` 条款库+公式表+阈值表（5 验算模块所需条目全部有 status）、`grading/` 危大阈值清单（相关条目原文核对）、`examples/` 算例真值库（≥10 例，来源登记）、合成方案生成器 v1（≥3 类注入+干净对照）、数据台账
- 演示物：`py -X utf8 tools/ 或 scripts/` 生成 fixtures；台账打印条款核对覆盖率
- DoD：①条款条目 100% 挂出处或"待核对"；②生成器两次运行位级一致（守门测试）；③fixtures CR 守门测试入仓；④EOL/冻结纪律测试全绿
- 回写：plan/00 状态表、05 里程碑、06 决策表、HANDOFF-M2

### M2 公式引擎（5 验算模块）

- 产出：`engine/` 5 模块 + 条款库加载器（待核对硬拦截）+ `sfc calc`
- 演示物：CLI 对算例输入卡出验算结果（应力比/结论/条款号）
- DoD：①算例真值通过率 100%（容差内）；②参数扫描回归锁定；③待核对拦截测试；④参数非法拒收测试
- 回写：同上 + README 基准表初版

### M3 方案核查与分级

- 产出：`parse/`（docx/pdf→参数卡）、`rules/`（构造限值核查+门控）、`consistency/`（两张皮）、`grading/`（危大判定器）、`sfc check` / `sfc grade`
- 演示物：CLI 对合成方案（注入 3 类缺陷）输出违规清单与分级结论
- DoD：①合成基准 dev 版达标（检出率 100%/误报 0/F1≥0.95）；②分级边界值用例 100%；③门控跨类目隔离测试；④低置信度"待人工确认"降级测试
- 回写：同上

### M4 内置基准与报告

- 产出：`bench/` 三套件 + `sfc bench`；`report/` 验算书/核查报告 docx
- 演示物：一条命令出全套指标；样例 docx 报告
- DoD：①基准零 API 可重复（断网跑通）；②报告 0 外链断言测试；③产物无时间戳位级一致测试（zip 元数据豁免表）；④指标写入 README
- 回写：同上 + 双基线复跑（解析 F1 + e2e）

### M5 桌面交付（GUI+exe）

- 产出：PySide6 五页签（只消费引擎 API）、PyInstaller onedir 双 exe、演示 GIF/截图、技术报告 md
- 演示物：exe 双通路（GUI 全流程 + CLI 控制台五连）
- DoD：①GUI offscreen 测试绿；②exe 干净验证（中立目录+env -i 剥离 PATH，不在仓库树内跑）；③数据内嵌分支测试锁死；④dist 无禁区成分+内嵌数据对账断言；⑤spec 白名单（版权红线数据不入包）
- 回写：同上

### M6 脱敏发布 GitHub + Release + 收尾

- 产出：GitHub 公开仓库、Release（exe+演示）、CI 四矩阵绿、收尾固化
- 演示物：GitHub 页 + Release 页
- DoD（发布门，逐项留档 plan/RELEASE-M6.md）：
  1. 干净环境验证：新目录 clone+全新 venv 按 README 逐字跑通；dev 与干净环境 pytest 收集数一致（逐项归因）
  2. 脱敏四步+产物本体扫描（固化成入仓脚本+守门测试）：tracked/内容级/二进制样例/历史三扫全 0；**系列表述公开性先核实**（`gh api` 查姊妹仓库可见性，未公开→移除系列表述再过扫描）
  3. 提交元数据邮箱检查（`git log --format="%ae %ce"` 全历史）→ 必要时 env-filter 改写 noreply
  4. 建仓注意 token 无 workflow scope→`gh repo create` 不带 `--push`，切 SSH push
  5. CI 首跑四矩阵绿；`gh run list` 对账 push 数=run 数
  6. Release/tag 经用户确认后打在 CI 绿的终态提交上；缓议项清零
- 回写：00/05/06 全 ✅ + HANDOFF-M7（完结收官）或就地收束
