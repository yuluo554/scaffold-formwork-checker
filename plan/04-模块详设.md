# 04 模块详设

> 本文给出核心数据结构的 schema 与模块设计。**条文纪律**：所有公式骨架仅表示结构形状，系数取值、限值数值、条款号以 [05-数据计划与里程碑.md](05-数据计划与里程碑.md) M1 原文核对结果为准；`status=待核对` 的条目不得进入计算路径（引擎加载时硬校验）。

## 1. 统一中间表示：参数卡（ParamCard）

验算输入卡（GUI/CLI 手填）、方案参数卡（从方案文本解析）、验算书取值卡（从验算书解析）共用同一 schema——两张皮检测=两卡字段对齐。

```jsonc
{
  "card_id": "scaffold-lh-001",          // 卡实例 id
  "card_type": "input | scheme | calcbook", // 输入卡/方案卡/验算书卡
  "category": "coupler_steel_pipe_scaffold | formwork_support",
  "entries": {
    "build_height":   {"value": 28.0, "unit": "m",
                       "confidence": 0.99,          // 输入卡恒 1.0；方案卡<阈值→待人工确认
                       "evidence": {"doc": "方案.docx", "locator": "第2章 2.1", "quote": "搭设高度28m"}},
    "step":           {"value": 1.8, "unit": "m", "...": "..."},      // 步距
    "long_spacing":   {"value": 1.5, "unit": "m", "...": "..."},      // 纵距
    "cross_spacing":  {"value": 1.05, "unit": "m", "...": "..."},     // 横距
    "wall_tie":       {"value": "two_step_three_span", "...": "..."}, // 连墙件两步三跨
    "wall_tie_v":     {"value": 3.6, "unit": "m", "...": "..."},      // 连墙件竖向间距
    "wall_tie_h":     {"value": 4.5, "unit": "m", "...": "..."},      // 连墙件水平间距
    "pipe_spec":      {"value": "48.3x3.6", "...": "..."},            // 钢管规格
    "steel_grade":    {"value": "Q235A", "...": "..."},
    "scissor_brace":  {"value": true, "...": "..."},                  // 剪刀撑设置
    "loads":          {"value": {"dead": 0.35, "live": 2.0, "wind": 0.35},
                       "unit": "kN/m2 等（分项单位进条目）", "...": "..."},
    "span_layout":    {"value": {...}, "...": "..."}                  // 模板支架：跨度/板厚等
  },
  "unknown_slots": ["..."]               // 宁缺槽位清单（解析失败/低置信度）
}
```

规则：参数合法性范围校验在卡片构造时执行（如步距∈(0, 2.0]m——**上限值待核对**），超范围即拒收并给原因；方案卡低置信度槽位进 `unknown_slots`，后续核查跳过该槽位而非硬判。

## 2. 条款库 schema（knowledge/clauses/*.json）

```jsonc
{
  "clause_id": "JGJ130-5.2.x",                 // 条款号待 M1 原文核对后回填
  "standard": "JGJ 130-2011",
  "clause_no": "5.2.x",
  "title": "立杆稳定性计算",
  "gist": "要点式转述（规避全文转载）：轴心受压/压弯稳定验算公式与系数取值",
  "formula_refs": ["F-stab-nw", "F-stab-w"],   // 指向公式表
  "thresholds_ref": "T-JGJ130-construction",   // 指向阈值表
  "status": "已核对 | 待核对",                  // 引擎加载时校验：待核对→相关模块拒绝运行
  "source": {"file": "原文文件名（raw/ 本地）", "channel": "官方渠道描述", "fetched": "2026-XX-XX"},
  "excerpt": "不超过一行的原文关键句摘录（短引用）"
}
```

配套两张机器可读表（引擎消费，随条款库同步核对）：

- **公式表 formulas.json**：`{formula_id, expr(变量符号式), params(符号→含义+单位+取值来源), applies_to, clause_refs, status}`。截面特性（φ48.3×3.6 钢管的 A/i/W 等）、钢材强度设计值 f、稳定系数 φ 的取值方法（λ→φ 查表或拟合式）全部登记 status。
- **阈值表 thresholds.json**：`{threshold_id, param, op(<=/>=), value, unit, condition(适用条件), clause_ref, status}`。构造限值（步距上限、连墙件间距上限等）与危大阈值分文件存放。

## 3. 五个验算模块详设（engine/）

每个模块统一契约：`calc(card: ParamCard, tables) -> CalcResult`；`CalcResult = {module_id, checks: [{item, expr, substituted, ratio(应力比/限值比), limit, verdict, clause_refs}], warnings, status}`。**verdict 只由确定性比较产生**；任一依赖条目 status=待核对 → 整模块返回"不可验算（依据未核对）"而非带病计算。

| 模块 | 公式骨架（结构，系数/条款号待核对） | 关键需核对项 |
|---|---|---|
| M-1 立杆稳定·不组合风 | 长细比 λ=l₀/i（l₀ 计算长度由步距×计算长度系数）→ 查稳定系数 φ → 应力 σ=N/(φA) ≤ f | 计算长度系数 k·μ 取值表、A/i、f、φ 取值方法（查表还是公式） |
| M-2 立杆稳定·组合风 | σ=N/(φA)+M_W/W ≤ f；M_W 由风荷载→立杆段弯矩（风荷体型系数、基本风压换算、挡风系数） | 风荷载组合方式、弯矩计算式、挡风系数取值 |
| M-3 纵/横向水平杆 | 抗弯 σ=M/W ≤ f；挠度 v ≤ [v]。M 分均布 q 与集中力 P（小横杆传力）两种模型，按简支/三跨连续取矩系数 | 矩系数、容许挠度 [v]（受弯构件限值表）、传力模型取舍 |
| M-4 连墙件 | 轴向力 N=风荷载作用力+约束力 N₀（数值待核对）→ 强度 σ=N/A_c ≤ f 与稳定双校核 | N₀ 取值、连墙件截面（钢管/型钢）与长细比限值 |
| M-5 立杆地基承载力 | p=N/A_底 ≤ f_g（f_g=地基承载力特征值×调整系数，调整系数待核对） | 调整系数、基础底面积算法（垫板尺寸）、f_gk 来源约定 |
| M-6 模板支架立杆稳定（JGJ 162-2008） | 荷载组合（模板及支架自重+新浇混凝土自重+钢筋自重+施工荷载+风）→ 立杆轴力 → 稳定验算（同 M-1 形状） | 162 规范的荷载分项系数、组合系数、计算长度取法、截面特性是否与 130 一致 |

## 4. 核查规则表 schema（rules/checks.json）

```jsonc
{
  "rule_id": "R-step-limit",
  "name": "步距不超过构造限值",
  "category": "coupler_steel_pipe_scaffold",
  "only_if": ["扣件式钢管脚手架", "落地式"],     // 类目门控关键词（互斥设计，对全部 check_type 生效）
  "check_type": "threshold | presence | consistency | grading",
  "param": "step",
  "op": "<=",
  "limit_ref": "T-JGJ130-step-max",            // 指向阈值表，不写死数值
  "level": "提示 | 不合格 | 严重",               // 三级判定
  "clause_refs": ["JGJ130-..."],
  "advice": "建议措辞模板",
  "status": "已核对 | 待核对"
}
```

check_type 分派：threshold=参数×限值比较；presence=必备项缺失（如漏剪刀撑、漏连墙件）；consistency=两卡字段 diff；grading=危大分级专用。**门控生效于全部 check_type**（conditional/checklist 分支最易漏接，系列实测坑）。

## 5. 一致性检测（"两张皮"，consistency/）

输入：方案参数卡 + 验算书取值卡（同一 schema）。流程：字段对齐（仅比对两侧都存在的字段）→ 数值容差比对（容差=字段定义，如长度类 0.01m）→ 差异清单 `{field, scheme_value, calcbook_value, delta, impact(对应验算模块与方向), advice}` → 不一致项按影响验算模块的安全方向定级（验算书取值优于方案实况=提示；劣于=不合格/严重）。两侧任一缺失字段→"待人工确认"，不硬判。

## 6. 危大分级判定器（grading/）

阈值清单 schema（grading/panorama.json，逐条挂 37号令/31号文）：

```jsonc
{
  "item_id": "pan-luodi-24",
  "project_type": "落地式钢管脚手架",
  "judge_params": ["build_height"],
  "levels": {
    "none":       {"cond": "build_height < 24", "label": "非危大"},
    "weida":      {"cond": "24 <= build_height < 50", "label": "危大工程",
                   "duty": "编制专项施工方案，施工单位审核+总监理工程师审查"},
    "chaoguimo":  {"cond": "build_height >= 50", "label": "超过一定规模",
                   "duty": "专项施工方案+专家论证"}
  },
  "basis": {"doc": "建办质〔2018〕31号 附件1/附件2", "clause": "...",
            "excerpt": "阈值原文短摘录", "status": "待核对"},
  "note": "24m/50m 两档已在题目阶段查证 ✅；全清单逐条原文核对后回填"
}
```

首期条目范围：31号文清单中与脚手架/模板支架相关条目（落地式钢管脚手架、悬挑式、附着式升降、混凝土模板支撑工程等，具体条目数以 M1 原文核对为准）。判定流程：工程类型识别 → 参数提取（手动输入或取自方案卡）→ 逐级条件比较 → 结论+义务提示+依据摘录。**判定准确率基准用例=清单条目×边界值±ε**（如 23.9/24.0/24.1、49.9/50.0/50.1）。

## 7. 报告导出（report/）

- **验算书 docx**：封面（工程名/编制/审核/日期手填）→ 参数卡表 → 逐项验算（公式、代入、结果、应力比、条款依据表）→ 结论汇总 → 签署栏 → **免责声明（强制，辅助工具不替代专项方案论证与审批）**。
- **核查报告 docx**：方案概况 → 违规清单（三级+条款+原文摘录）→ 两张皮差异清单 → 危大判定结论+义务提示 → 待人工确认项 → 免责声明。
- 确定性纪律：内容字段无时间戳（签署栏手填）；python-docx 生成；0 外链断言（docx 内无 `TargetMode="External"` 超链关系）。

## 8. GUI 结构（gui/，M5）

页签式（QTabWidget），每页只调引擎 API：

1. 验算页：模块选择 → 动态参数卡表单（按模块字段生成，带合法性即时校验）→ 结果表（应力比/限值比/结论/条款号）→ 一键导出验算书
2. 方案核查页：文件选择 → 解析进度 → 参数卡回显（低置信度槽位标黄=待人工确认）→ 违规清单树 → 导出核查报告
3. 一致性页：方案文件+验算书文件 → 差异表
4. 危大分级页：类型+参数表单 → 判定卡（结论/义务/依据摘录）
5. 基准页：跑内置基准 → 指标表（同 README 表数据源）

## 9. bench 基准（bench/）

- `examples` 套件：算例真值库逐例跑引擎，容差比对，输出通过率（目标 100%）。
- `synthetic` 套件：合成方案（干净对照+注入缺陷组）跑解析+核查，输出字段级 P/R/F1、每类缺陷检出率、误报率（目标 0）。
- `grading` 套件：分级判定用例表，输出准确率（目标 100%）。
- 全套零 API、离线、固定 seed；`sfc bench` 一条命令跑完，指标写 README 表。
